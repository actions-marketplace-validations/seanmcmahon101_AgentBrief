# AgentBrief design

This document records what AgentBrief is for, the decisions behind it, and the
contracts between its packages. Read it before changing behaviour.

## The problem

Before a coding agent can make a correct change it needs a handful of
operational facts: which package manager and toolchain version to use, the exact
build / test / lint / typecheck commands, how to run a *single* test, which
files are generated and must not be hand-edited, and where package boundaries
are in a monorepo. Agents rediscover these every session by reading manifests,
CI files and READMEs, and they still get them wrong (`npm install` in a pnpm
repo, editing generated code, running the whole test suite to check one file).

The usual fix is an `AGENTS.md` / `CLAUDE.md`. The evidence on those files is
sobering:

- Gloaguen et al. (ETH Zurich, ICLR 2026, arXiv 2602.11988) found
  **LLM-generated** context files slightly *reduced* task success and raised cost
  by ~20%. Developer-written files helped by ~4%. Overviews and directory
  listings did not help agents find the right files. Agents do follow concrete
  tool instructions (mentioning `uv` made agents use it).
- Instruction files rot. Commands get renamed, paths move, the package manager
  changes, and nothing tells you. Agents follow stale instructions faithfully.
- With several agents in play, files duplicate and contradict each other, and
  precedence rules differ (Claude Code ignores `AGENTS.md` when a `CLAUDE.md`
  exists unless it imports it with `@AGENTS.md`).

## What AgentBrief does

AgentBrief is a deterministic, local CLI. It **derives** operational facts from
repository files (manifests, lockfiles, task runners, CI workflows, toolchain
pins), **writes** a small, sourced block of them into `AGENTS.md`, and **checks**
in CI that the block and every other agent-instruction file still match the
repository.

Why a tool instead of asking an agent to write `AGENTS.md`:

1. **Verified, not guessed.** Every fact comes from a file AgentBrief can name.
   It never invents commands. Commands also run in CI are marked as such.
2. **Small by construction.** It emits only the facts research shows matter,
   and never an overview, directory tree or style advice.
3. **Stays true.** `agentbrief check` fails CI when the generated block is stale
   or when hand-written instructions reference scripts, targets or paths that no
   longer exist. No LLM-written file can do this for itself.
4. **Free and instant.** It uses no tokens and needs no API key, and a scan takes
   milliseconds. Its output is byte-for-byte reproducible.
5. **Works for every agent.** It writes one canonical `AGENTS.md`, plus import
   shims (`@AGENTS.md`) for agents that would otherwise not read it. Agents can
   also query it on demand: `agentbrief brief <path> --json`.

Non-goals:
- Repository dumps or symbol maps (Repomix and Aider already do these well).
- LLM calls.
- Architecture prose.
- Style guides.
- Nested per-package `AGENTS.md` generation. It may come later; in v1 the
  per-package detail is served on demand by `brief <path>`.

## Commands

```
agentbrief [brief] [PATH] [--json] [--all]    print the brief (default command)
agentbrief sync [--dry-run] [--no-imports]    write/refresh the managed block in AGENTS.md
agentbrief check [--json] [--strict]          verify the block is current; lint instruction files
agentbrief version
```

Global: `-C DIR` sets the repository root (default: nearest ancestor containing
`.git`, else the current directory).

- `brief PATH` scopes the output to the project that owns PATH (the nearest
  project whose Dir is a prefix of PATH). It shows that project's commands and
  then the root commands that still apply. `--json` emits the structured brief,
  and `--all` emits the full `model.Repo`.
- `sync` is idempotent. If nothing material changed, the file is not rewritten
  and the command says so. It only ever touches the text between the markers,
  plus a one-line `@AGENTS.md` import added to an existing root `CLAUDE.md` /
  `GEMINI.md` that lacks one (skip with `--no-imports`). If `AGENTS.md` does not
  exist, sync creates it.
- `check` exits 0 when clean, 1 when there are errors (or warnings with
  `--strict`), and 2 on usage or IO errors.

## Output contract: the managed block

```markdown
<!-- agentbrief:start -->
## Repository facts

_Generated by [AgentBrief](https://github.com/seanmcmahon101/AgentBrief) from repository files; do not edit inside this block. Refresh with `agentbrief sync`._

- Toolchain: Node 20 (`.nvmrc`), pnpm 9.12.0 (`package.json` packageManager). Use pnpm, not npm or yarn.

Commands (run from the repo root):
- install: `pnpm install --frozen-lockfile` (CI)
- build: `pnpm build` (package.json, CI)
- test: `pnpm test` (package.json, CI)
- single test: `pnpm vitest run <file> -t "<name>"` (vitest)
- lint: `pnpm lint` (package.json, CI)

Workspace (pnpm, 12 packages): `packages/core` (@acme/core), `packages/ui` (@acme/ui), … — `agentbrief brief <dir>` shows a package's own commands.

Do not edit by hand: `src/gen/**` (generated; `pnpm codegen`), `pnpm-lock.yaml`.
<!-- agentbrief:end -->
```

The rules:
- **Deterministic.** The same repository gives the same bytes. The block carries
  no timestamps, durations or absolute paths.
- **Budget.** Aim for 40 lines or fewer. Lists are truncated with "…" and a pointer
  to `agentbrief brief`.
- **Provenance.** The source is shown in parentheses. `CI` means a CI workflow runs
  the command.
- **One command per kind** in the block: the best one. The order of preference is:
  1. declared and run in CI
  2. declared
  3. run in CI
  4. convention

  At equal evidence, the repo's own task runner (npm script, make target, …)
  wins over the raw tool. Convention-only commands are shown only when nothing
  better exists.
- **Prose.** The block never copies free-form prose from the repository, such as
  README text or task descriptions. It copies only identifiers, paths, versions
  and command lines. Command lines are code-formatted, length-capped (160 chars)
  and passed through secret redaction. This limits prompt-injection and
  secret-leak surface.
- **Empty sections are omitted.** If AgentBrief finds nothing, the block says so in
  one line rather than padding.

## Check rules (`agentbrief check`)

| Rule | Severity | What it means |
|---|---|---|
| `stale-block` | error | The managed block differs from what `sync` would write now. |
| `unknown-script` | error | An instruction file tells agents to run a script, target or task that does not exist: `npm run X` / `pnpm X` / `yarn X` / `bun run X`, `make X` (including `make -C dir X`), `just X`, `task X`, `mise run X`, `composer X`, `poe X`, `tox -e X`, `nox -s X`, `cargo … -p X` (workspace crates), `docker compose up X` (services). Warning instead of error when the inventory may be incomplete. |
| `missing-path` | error for Markdown links and paths inside commands; warning for code spans and prose | A referenced repository path does not exist: Markdown links, code spans that look like paths, and path arguments of commands such as `pytest tests/x.py`, `python scripts/x.py`, `bash scripts/x.sh`, `go test ./pkg/...`. |
| `wrong-package-manager` | warning | The instructions use one JS/Python package manager but the lockfile says another. |
| `agents-md-not-loaded` | warning | Root `CLAUDE.md` exists and `AGENTS.md` exists, but `CLAUDE.md` doesn't import it. Claude Code will not read `AGENTS.md`. The same applies to `GEMINI.md`. |
| `oversized` | warning | The file is over 32 KiB (Codex's default cap) or `CLAUDE.md` is over 200 lines (Anthropic's guidance). |

The rules avoid false positives: placeholders (`<file>`, `$VAR`, `{x}`), globs,
URLs, absolute paths and built-in package-manager subcommands (`pnpm install`,
`yarn add`, `npm ci`, …) are not reported. Fenced code blocks are linted
for commands but not for paths.

## Architecture

```
cmd/agentbrief        main: calls cli.Main(os.Args, stdout, stderr) and exits
internal/cli          argument parsing (stdlib flag), command dispatch, exit codes
internal/scan         read-only, safety-filtered view of the repository (gitignore, size caps, secret deny-list)
internal/redact       secret redaction for any string that reaches output
internal/detect       ecosystem detectors -> model.Repo (one file per ecosystem, registered via init)
internal/model        the fact types and JSON schema (agentbrief/v1)
internal/brief        curation (pick best facts, scope to a path) and rendering (Markdown block, JSON)
internal/instructions discover instruction files, managed-block read/write, sync, check rules
```

Data flow: `scan.Open` produces a `*scan.Repo`, `detect.Run` turns it into a
`*model.Repo`, and from there:
- `brief.Build(repo, scope)` produces a `brief.Brief`, rendered as Markdown or JSON.
- `instructions.Sync` writes the brief's Markdown block into `AGENTS.md`.
- `instructions.Check` produces `[]model.Finding`.

Dependencies are deliberately few: the Go standard library,
`github.com/BurntSushi/toml` and `go.yaml.in/yaml/v3`.

## Security model

Repository contents are untrusted.

- AgentBrief **never executes** anything from the repository, and that includes
  `git`. A repository's `.git/config` can run commands through hooks such as
  `core.fsmonitor`.
- Files matching the sensitive-file list (`.env*`, keys, credentials) are never
  read. `scan.Repo.Read` enforces this.
- Symlinks are not followed. Reads are capped at 1 MiB.
- Any repository-derived string written to output is length-capped and redacted,
  and no free-form repository prose is copied into generated instruction blocks.
- `sync` writes only to `AGENTS.md`, `CLAUDE.md` and `GEMINI.md` at the root.
  It changes only the text between its markers and the single import line.
